# Ione 论文方法与 Agent 实验：证据、结论及边界

2026-10-28。本报告按“论文问题 → 对应方法 → 本项目可检验问题 → 原始结果 → 审计后结论”整理。所有模型原文和逐题判分见 [第一轮 12 题](paper_feedback_eval.json) 与 [事实锚点 28 题](fact_anchor_eval.json)；运行协议分别见 [第一轮](paper_feedback_experiment_protocol.md)、[第二轮](fact_anchor_experiment_protocol.md)、[审计后新验证](fact_anchor_verification_protocol.md)。

## 1. 论文到底和项目有什么联系？

[Rao et al., *Collaborative Quest Completion with LLM-driven Non-Player Characters in Minecraft*](https://arxiv.org/html/2407.03460v1) 研究玩家怎样与 GPT-4 驱动的 Minecraft NPC 合作完成任务，包含 28 名玩家的游戏观察。其 NPC 有专属人设和背景、受限的游戏 API、目标/子目标以及自由文本交流。论文的一个明确工程问题是：**工具调用失败后，如果 NPC 不知道失败，可能仍告诉玩家“我已完成动作”**。作者把函数成功/失败回值和示例放进下一次响应提示，让 NPC 在失败时给出合适解释；论文还讨论缺少丰富实时世界状态时的错误回答。见论文 §2.2 *Game API functions / Function response / Constraints* 和 §3.3。

Ione 对应的是这个较窄的**函数回执到玩家可见回答**问题：玩家问路线、请求打开档案门或询问档案所有者时，如何让小模型的台词与真实世界状态、权限和工具结果一致？我们另外实现了回合版本取消和四姿态接口；这两者**不是**该论文提出或验证的方法。Ione 也没有复现 Minecraft 协作任务、GPT-4、28 人用户研究或其子目标生成实验。

## 2. 先做论文直接启发的方法，再找第一偏离点

固定 12 个作者编写场景，对比同一次首阶段 Gemma 3 4B 输出、无回执再生成、把真实工具回执给模型再生成、确定性模板。温度 0，所有世界快照独立重置，二次生成各调用一次。本轮只是**单回合、离线、文本层**。事先规则要求回答点名被问路线及状态、故障目标、是否开门/为何拒绝、当前所有者，不能只讲模糊安慰话。

| 方法 | 可用且回答目标事实 / 12 | 额外生成耗时 P50 |
| --- | ---: | ---: |
| 工具前首阶段模型原文 | 0 | 无二次生成 |
| 无工具回执，模型再生成 | 0 | 7.25 秒 |
| 真实工具回执，模型再生成 | 1 | 8.38 秒 |
| 确定性模板（逻辑上限） | 12 | 0 |

**结论一：**在这个小模型和提示合同下，单纯给状态回执没有可靠地解决“告诉玩家发生了什么”。例如东桥坍塌、西廊开放时，它只说“路很乱，小心脚下”；西廊开放时它说有瓦砾堵住；旧档案已被实时查询纠正时仍重复旧所有者。论文的方案包含 GPT-4、精心编排的状态示例与更丰富的任务环境；这里的失败不构成对论文结论的反证，而是本项目实现条件下的观察。

## 3. 事实锚点、模型口吻与发布门禁

根据上述失败，增加 `FactCard`：工具层生成不可改写的目标事实句和建议姿态；模型看到该句后生成短回复；发布前检查事实句是否原样保留，并由工具层决定最终姿态。模型原文的评分只检测**任务目标事实是否交代清楚**，不等于整句都无虚构。发布门禁采用保守的角色短句白名单；任意其他后缀退回事实句。与论文的回执示例相比，这是 Ione 的**独立工程扩展**，不是论文原方法或其效果的复现。

| 数据划分 | 回执模型：目标事实通过 | 事实锚点模型：目标事实通过 | 发布后目标事实通过 | 最终保留模型附加台词 | 二次生成 P50：回执 → 锚点 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 开发 12 题（用于修改方法） | 1/12 | 12/12 | 12/12 | 0/12 | 8.38 → 8.75 秒 |
| 首批挑战 8 题（后来用于发现评分缺陷） | 3/8 | 7/8 | 8/8 | 0/8 | 8.28 → 8.81 秒 |
| 评分修订后新验证 8 题 | 3/8 | 8/8 | 8/8 | 2/8 | 8.53 → 10.05 秒 |

新验证中，模型能准确复述“东桥和西廊都坍塌”“玩家自称所有者但门仍锁定”“门本来就已打开”等事实；旧回执方案常只说一个通道、含糊提及门锁或不说明动作结果。**可复述率的提高来自模型收到了完整事实句和建议姿态**，不能解释为它自行推理世界状态的能力提高。发布后的 8/8 是程序合同加兜底的效果，不能当模型准确率。

## 4. 审计修订和反面发现

首次自动评分把“地图坏了”但未点名玩家所问路线、以及“门本来已开，但这次调用起了作用”误计为通过；双路线问题的事实卡也只说了东桥。修订后重新对**原始模型缓存**评分，未覆盖旧输出：第一轮回执组由 3/12 变为 1/12，事实锚点首批挑战原文由 8/8 变为 7/8。`h01` 的旧模型回答缺失西廊状态，发布门禁在修正后的事实卡上回退。随后固定并运行 `j01`–`j08` 新验证题，结果如上。此过程属于开发与审计，不是严格盲测；指标以修订后报告为准。

更重要的二次人工复核发现：即使目标事实正确，Gemma 仍可能附加未核验世界细节，例如“水更深”“那人是男性”。因此最终发布策略只接受预先批准的非事实角色短句；新验证 8 条中只有 2 条完整保留，另 6 条回退为事实句。**结论二：事实锚点提升目标事实复述；开放式角色口吻仍需要更好的内容校验与作者设计。** 当前安全性来自小范围事实模板与保守门禁，不是对任意自然语言的语义正确性保证。

## 5. 与 Unreal Engine 虚拟人实验的关系及缺口

角色 Ione 的视觉决策包括黑色新生发根与褪色金发、旧帽、单侧圆形磁带听觉装置、修补工装外套和全身四姿态。Unreal Engine 5.8.4 中已编译 C++/Blueprint 演员、导入四张 `Texture2D`、在游戏窗口运行世界空间朝向相机的 `PortraitWidget`；Listening / Speaking / Interrupted / Warning 可由测试按键切换，见 [UE 运行截图](ue5_ione_stage/README.md)。Agent 的 `FactCard.expression` 给出了与工具结果一致的姿态合同，但**自然语言输入→模型→工具→UE 实时表演尚未端到端接线**。故本实验不能证明角色动作、表情、玩家沉浸感或真实流式打断体验得到改善。

先前 [30 场景离线消融](agent_eval_summary.md) 的另一结论是：加回合版本检查后，8 个打断后的旧工具尝试由 8/8 降到 0/8；这是程序门禁/状态机验证，不是论文回执方法的收益，也不是 UE 内打断实测。30/30 的最终通过数是作者固定题上的合同检查结果，不应宣传为泛化成功率。

## 6. 下一步研究条件

需要更大且独立编写的多轮任务、盲法人工评估台词自然度/角色感，以及真实 UE 对话框、流式输出和 `PlayerInterrupt` 联动录屏。当前 28 个响应题一题一次调用，且第二轮同时引入事实句、few-shot 示例、建议姿态与门禁，不能分离各组件的因果贡献；新验证题也是作者设计，不能推出统计显著性。额外模型生成约 8–10 秒 P50，不宜把该延迟包装为“实时”玩家体验。
