# 第三轮预设：可玩的 NPC 回答质量与延迟

冻结日期 2026-10-28，开始新模型调用前。动机来自 [TCQA², REALM 2025](https://aclanthology.org/2025.realm-1.20/) 的分层意图路由/游戏知识/工具/评论员架构与 [Arm First Contact](https://developer.arm.com/community/arm-community-blogs/b/mobile-graphics-and-gaming-blog/posts/first-contact-a-mobile-architecture-for-llm_2d00_powered-game-characters) 的消费级硬件上先测模型推理和引擎集成。此项目不复现它们的数据集或产品效果。

## 可证伪的问题

在这台 Intel i5-1240P / 16GB RAM / Iris Xe 机器上，能否用**一次低成本自然语言意图解析 + 确定性游戏工具与作者台词**，同时满足：完整任务正确率不低于旧 Gemma 3 4B 双阶段 Agent、无未经授权的世界改动、玩家可见 P50 明显低于旧 Agent？若小模型无法正确解析难题，应如实报告、保留较慢的回退，而非把规则路径的效果写成模型推理能力提升。

## 同题对照

- **B0**：已实现的 Gemma 3 4B 首阶段 JSON 提议→单工具提交→事实锚点二次生成→发布门禁。每题重新调用模型，记录完整墙钟、模型耗时、工具结果、玩家可见台词和姿态。
- **B1**：新小模型 Qwen3 0.6B（若格式/正确率不达标则可测 1.7B，留存失败记录），只输出结构化意图、最多两个路线目标，不自由生成事实台词。上下文只含必要角色/工具合同；不把权威世界答案直接给解析模型。记录路由准确率和耗时。
- **B2**：B1 计划交给现有 `ToolGate`；一次问题可并行/顺序检查两条路线，作者台词从工具回执编译；固定姿态由回执和安全状态决定。对否定命令、授权与新回合版本进行确定性守卫。记录模型路径/规则路径/回退路径，不把预写台词算成模型生成能力。

## 20 个固定任务和判分

在 `Tools/eval_fast_agent.py` 内固定 R01–R10、D01–D05、M01–M03、C01–C02。路线涵盖东/西通路开放、坍塌、双路线取舍和地图故障；门包含未授权、授权、谎称授权、已经打开、明确禁止开门；档案包含旧记忆冲突；闲聊禁止误触工具。每题独立 `World` 快照，绝不复用已修改的门状态。

**主要终点**：任务成功 = 正确意图/目标 + 工具/权限/世界最终状态正确 + 玩家可见台词回答被问事实/行动结果；所有条件同时满足。严格评分器检查路线实际状态与建议、授权和开门结果、档案当前所有者，以及禁止命令无工具调用。另记录目标解析正确率、越权/过期动作数、P50/P95 热模型墙钟、token、最慢和失败样本。首轮为作者编写小样本；根据失败修复后必须另起新题，不能在同一题上报“留出集”提升。

不以 100% 为目标调答案。若 B2 通过率与延迟无法兼顾，结论是该设备/模型组合目前不适合实时 NPC，简历不使用夸大指标。

## 第一轮后修订记录

首轮 B0 16/20、0.6B B2 10/20。0.6B 在路线任务速度快，但最初 `targets` 数组 schema 迫使非路线意图也填入两个路线目标并触发解析异常；两条否定命令误判为路线。修订为单个 `route_target` 枚举，非路线意图不接收路线目标；明确的否定命令先走无动作安全入口。1.7B 模型作为预设的候选替换。旧原始结果留在 `fast_agent_20.json`，新模式单独记录；这 20 题此后是开发集，不能再称留出集。需要修订后另建新验证题。
